# Bug: data changes or disappears on a normal refresh
This is a persistence bug, not a feature.

Required save rules:
1. There is one stored blob in localStorage key okvSpendSmart.
2. It must include: tabs, columns, entries, bills, Box 3 expected income + frequency, budgets, rules, theme, selected view/date, lastBackupAt.
3. Write that blob synchronously after EVERY committed action (add/edit/delete entry, add bill, add funds, mark paid, tab/column change, Box 3 change, theme). Do not wait for beforeunload.
4. Also flush a snapshot every 60 seconds if state is dirty.
5. On boot: READ storage first. If a blob exists, use it. Seed Bills/Food/… only when storage is empty.
6. Do not save until hydration from localStorage has finished (hydrated flag). Saving empty seed over real data is the usual refresh bug.
7. After a successful write, UI badge = “Saved just now” and lastBackupAt = now. “Never backed up” is wrong after the user has added anything.

If inputs in an open modal vanish on refresh, that is OK. If a saved bill, expense, expected amount, or tab color resets, that is a bug — fix it.
